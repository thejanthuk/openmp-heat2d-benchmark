## What happened, in order

1. **A refactor silently deleted every validation check** (the ones ADR-003 was written for).
   Nothing failed, because nothing tested that bad input is rejected. Fix: `tests/test_config.cpp`.
2. **Testing the test:** removing the `n_interval_x` check made the test fail with its own message.
   A test you have never seen fail may not be testing anything.
3. **A suite of only "should throw" cases passed a `make_config` that throws on every call.** Fix: a
   positive case — a valid config must NOT throw and must hit `rx + ry = 0.5 * default_coeff`.
4. **The stability `require` is no longer reachable by any input.** With `coeff` in (0, 1),
   `rx + ry = coeff/2 < 0.5` by construction. 225 configs (aspect ratios up to 65536:1, largest
   allowed `coeff`): fired 0 times, max `rx+ry` exactly 0.5. It now guards the *formula*, not input.
5. **The positive test caught a real bug**: defaults were half-migrated (constants used in
   `parse_args`, literals still in `make_config`'s signature). Changing `default_coeff` made the CLI
   and the API silently disagree (0.7 vs 0.8), and the test failed. First bug found by my own test.
6. **Sabotaging the `dt` formula (x2 -> x1.9) gave `rx + ry = 0.421` — under 0.5, so the stability
   `require` stayed silent. Only the positive test caught it.** A test with an exact expected value is
   stricter than a guard with a bound.

## Later: quest 1 complete — the serial solver runs and is correct

Krit wrote `field.hpp` (the free `index(i, j, n_point_y)` plus an `Indexer` holding `n_point_y`, so
call sites read `index(i, j)`) and `src/serial/main.cpp`. After review fixes — missing `<memory>`;
`heat::index(i, j)` resolving to the 3-argument free function instead of the local `Indexer`; an
initial condition that ignored `length_x`/`length_y`; empty stub files breaking the link — the CMake
build, both tests, and every comparison against the exact solution pass:

| Run | Centre | Exact |
|---|---|---|
| square, `0 100 100 500` | 0.820850 | 0.820869 |
| Lx=1, Ly=0.5, equal n | 0.820850 | 0.820869 (was 0.648 before the IC fix) |
| Lx=1, Ly=0.5, n_point_x != n_point_y (100x50) | 0.610434 | 0.610498 |

Two lessons worth keeping:

- **The non-square IC bug ran silently and printed a plausible number** (0.648, 21% off). Only a
  comparison against the exact solution caught it.
- **Every earlier run had n_point_x == n_point_y, which cannot reveal a transposed index formula**
  (`i*nx + j` and `i*ny + j` coincide). The 100x50 run is the first that could. Quest 2's convergence
  test should therefore include a non-square domain *and* unequal point counts.

Also verified: an `Indexer{int}` passed with `firstprivate(index)` works inside a GPU target region,
unlike the earlier pointer-carrying `View`, because it contains no host address.
