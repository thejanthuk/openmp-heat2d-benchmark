## Which comes first: the GPU pair, not the roofline graph

Krit asked what to do for the naive GPU offload step, and whether to implement versions 3 and 4 or
the roofline graph first. Claude read the supervisor's spec before answering rather than reasoning
from the repo alone. §6.3–6.4 settle it:

| Week | Focus | Expected output |
|---|---|---|
| 3 | GPU offloading | naive offload + correctness verification |
| 4 | GPU optimization | `target data` version, benchmark table, speedup graph, report |

**"Roofline" does not appear in the spec.** It is Krit's own analysis layer, and by the spec's own
ordering it is Week-4 material. Three further reasons to build the GPU pair first:

1. The plot needs four points from *this* repo. The only GPU numbers on record (13.15 s, and the
   12.64 s naive−optimized gap) came from the C implementation in a separate repository, built
   `-O2` without `-march=native`. Plotting those would graph a different experiment.
2. The offload toolchain is the schedule risk and it fails silently. Claude confirmed host GCC
   16.2.0 and `nvptx-none-gcc` 16.2.0 match and `mkoffload` is present, but file presence is not
   proof — the probe must be re-run under `OMP_TARGET_OFFLOAD=MANDATORY`.
3. The axes are not decidable yet. With a fixed ~0.42 flop/byte kernel there is one x-value; whether
   the figure is one roof or two (host and device, with different ceilings) is easier to settle with
   the measurements in hand.

**The distinction drawn:** the roofline *arithmetic* — bytes moved ÷ measured ceiling — is the
prediction and is due **before** the run. The *plot* is a presentation of results. So the numbers go
into `NOTES.md` now; the figure comes in Week 4.

Claude also recommended building naive and optimized in one sitting despite the spec splitting them
across weeks: they are one experiment, the measurement *is* their difference, and they share a single
toolchain fight.

Guidance given for the naive step covered the file layout CMake already dictates
(`src/openmp_gpu_{naive,optimized}/main.cpp`), the design questions to settle before typing the
kernel (which arrays cross each step and in which direction; what happens to boundary values if the
output buffer is only copied out; that `unique_ptr`/`swap` do not cross to the device), two traps
(`assert` is stripped in Release so the `omp_is_initial_device()` check must use `require()`; the
`Indexer` may need `declare target`), and done-criteria including a differential test at **both an
odd and an even** step count. Per the working agreement, no solver code was written.

One review finding on the build: `CMakeLists.txt` passes `-fno-stack-protector` and `-lm` to the
device but **not `-O3`**, while the command line documented in `CLAUDE.md` does. It does not affect
the naive−optimized gap, only comparisons of absolute times against the old 13.15 s.

### A second rewrite: the commits were attributed to the wrong account

The noreply address baked into every commit belonged to an account other than the one that would host
the repository. GitHub resolves a noreply address by the numeric id inside it, so all 20 commits would
have displayed as authored by the wrong account — its avatar, its profile, its contribution graph. On a
repository whose stated purpose is authorship evidence, that is the wrong outcome.

A second `filter-branch --env-filter` pass rewrote author and committer email to the correct address,
and the local `git config user.email` was changed to match so later commits do not drift back. The hash map above is stated in terms of the **final**
hashes, after both rewrites; the intermediate hashes from the first rewrite are not recorded because
they were never pushed anywhere.

**Worth knowing:** the noreply address is not cosmetic. `id+name@users.noreply.github.com` binds a
commit to an account by id, so a stale one silently mis-attributes work. It is worth checking before
the first push of any repository that is meant to evidence authorship.

**Why his name stayed.** His account, his handle and every commit's author field already name him,
and `AUTHORSHIP.md` exists to attribute the work. Removing it would anonymise nothing and destroy the
evidence the repository is for. The initial commit's author name was normalised to match the rest.

**The supervisor's two documents** moved to `docs/private/`, ignored as a *directory* — the previous
rule named the file, so the ignore rule itself had to go.

**`README.md`** was the hosting platform's generated boilerplate, including the institutional group
URL twice. Substitution could not fix that; it was replaced with a real README.

### Two method notes worth keeping

- **A blind find-and-replace produces broken prose.** Trialling the script on a throwaway clone first
  caught four failures — `"the old an earlier local guide guide"`, a lowercase sentence start, a
  doubled `"clash with the supervisor's, the supervisor's"`, and gendered pronouns for someone whose
  pronouns are not stated. All were fixed before touching the real history.
- **Literal rules miss historical spellings.** The first pass replaced a remote URL in the form the
  *current* file used, leaving an older version of that same line, which named the other account,
  untouched in an intermediate commit. A regex fallback pass now catches any `git@github.com:…` URL
  and any bare occurrence of the removed identifiers, whatever surrounds them. **When rewriting
  history, match patterns, not the sentences in front of you.**
- **Verify with a pattern that matches only what you meant to remove.** A check that included Krit's
  surname reported 7 "leftover" blobs which were his own name in `AUTHORSHIP.md`, deliberately kept.
